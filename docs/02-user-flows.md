# 신혼OS 사용자 플로우

## 1. 문서 목적

이 문서는 신혼OS MVP의 핵심 사용자 흐름을 화면 단위로 정리한다. 구현 상세가 아니라, 사용자가 어떤 순서로 이동하고 어떤 예외를 만나는지 정의하는 문서다.

신혼OS는 개인보다 커플을 중심으로 한다. 중요한 흐름은 한 명이 끝내는 것이 아니라, 커플 생성, 배우자 참여, 공동 입력, 비교, 공동 승인, 상담 신청으로 이어진다.

## 2. 공통 화면 원칙

- 모바일 화면을 기본 기준으로 본다.
- 모든 주요 화면에는 로딩, 에러, 빈 상태가 있어야 한다.
- 정책, 가격, 상담 신청 화면은 사용자가 확정 또는 보장으로 오해하지 않게 표현한다.
- 소득, 자산, 보유 현금 등 민감 정보는 가능한 한 구간으로 입력한다.
- 배우자가 아직 참여하지 않은 상태에서는 "혼자 먼저 볼 수 있는 화면"과 "둘 다 참여해야 하는 화면"을 구분한다.
- 상담 신청 전에는 개인정보 제공 동의와 전송 전 확인 화면이 필요하다.

## 3. 전체 핵심 흐름

1. 가입 또는 로그인
2. 커플 생성
3. 배우자 초대
4. 배우자 초대 수락
5. 공동 온보딩
6. 시나리오 생성
7. 시나리오 결과 확인
8. 정책 매칭 결과 확인
9. 파트너 상품 비교
10. 비교방 생성
11. 둘 다 승인
12. 상담 신청

## 4. 가입 → 커플 생성 → 배우자 초대 → 수락

### 4.1 기본 흐름

#### 화면: 시작 화면

목적:
사용자가 신혼OS의 첫 진입점에서 가입 또는 로그인을 선택한다.

표시 요소:

- 서비스 이름
- 짧은 설명: "우리 둘의 예산, 정책, 선택지를 함께 정리해요"
- 가입 버튼
- 로그인 버튼
- 개인정보와 금융성 안내 링크

사용자 행동:

- 새 사용자는 가입을 선택한다.
- 기존 사용자는 로그인을 선택한다.

#### 화면: 가입 화면

목적:
사용자를 생성한다.

입력:

- 이름 또는 닉네임
- 이메일 또는 휴대폰 기반 식별자: 확정 필요
- 약관 동의
- 개인정보 처리 동의

주의:

- 주민등록번호는 받지 않는다.
- 마케팅 동의는 필수 동의와 분리한다.

완료 후:

- 커플 생성 화면으로 이동한다.

#### 화면: 커플 생성 화면

목적:
사용자가 신혼OS의 기본 단위인 커플을 만든다.

입력:

- 커플 표시 이름: 예시 "우리 결혼 준비"
- 본인 역할 또는 호칭: 확정 필요
- 결혼 준비 상태: 예비 신혼 / 혼인 후 / 확정 필요

완료 후:

- Couple 생성
- CoupleMember에 본인을 owner 또는 member로 추가: 역할명 확정 필요
- 배우자 초대 화면으로 이동

#### 화면: 배우자 초대 화면

목적:
배우자가 같은 커플 공간에 참여하도록 초대한다.

표시 요소:

- 초대 링크
- 링크 복사 버튼
- 공유 버튼
- 초대 만료 시간
- "배우자가 아직 없어도 먼저 시작할 수 있어요" 안내

사용자 행동:

- 초대 링크를 복사하거나 공유한다.
- 배우자 참여를 기다리지 않고 온보딩 일부를 먼저 시작할 수 있다.

완료 후:

- 초대 발송 상태를 저장한다.
- 홈 또는 온보딩 시작 화면으로 이동한다.

#### 화면: 초대 수락 화면

목적:
배우자가 초대 링크를 열고 커플에 참여한다.

표시 요소:

- 초대한 사람 이름 또는 닉네임
- 커플 표시 이름
- 초대 만료 여부
- 참여 버튼
- 거절 또는 나중에 하기 버튼

사용자 행동:

- 비회원이면 가입 후 초대 수락을 이어간다.
- 회원이면 바로 초대를 수락한다.

완료 후:

- CoupleMember로 배우자를 추가한다.
- 공동 온보딩 화면으로 이동한다.

### 4.2 분기와 예외

#### 이미 로그인한 사용자가 시작 화면에 진입

- 커플이 없으면 커플 생성 화면으로 이동한다.
- 커플이 있으면 홈 화면으로 이동한다.
- 이미 초대 대기 중이면 초대 상태 화면을 보여준다.

#### 가입 중 이메일 또는 휴대폰이 이미 사용 중

- 로그인 안내를 보여준다.
- 기존 계정으로 로그인 후 기존 진행 상태를 복구한다.

#### 커플 생성 실패

- 네트워크 오류: 다시 시도 버튼 표시
- 서버 오류: 잠시 후 다시 시도 안내
- 입력 오류: 해당 필드 아래에 쉬운 한국어로 안내

#### 배우자가 초대를 열었지만 초대가 만료됨

- "초대 링크가 만료됐어요" 화면 표시
- 초대한 사람에게 새 초대 요청 버튼 제공
- 초대한 사람 화면에는 새 초대 링크 만들기 버튼 표시

#### 배우자가 이미 다른 커플 소속임

- 바로 참여시키지 않는다.
- "이미 다른 커플에 참여 중이에요" 안내 표시
- 기존 커플 확인 또는 고객지원 문의 안내
- 커플 이동 또는 탈퇴 정책은 확정 필요

#### 초대한 사람이 초대 링크를 취소함

- 수락 화면에서 취소된 초대 안내
- 새 초대를 요청하도록 안내

#### 배우자가 초대 수락을 거절함

- 초대한 사람에게 거절 상세 사유를 노출하지 않는다.
- 초대 상태는 rejected 또는 expired와 구분한다: 확정 필요

## 5. 공동 온보딩 → 시나리오 생성 → 결과 확인

### 5.1 기본 흐름

#### 화면: 온보딩 시작 화면

목적:
커플이 함께 입력해야 할 정보와 예상 소요 시간을 안내한다.

표시 요소:

- 진행률
- 본인 입력 상태
- 배우자 입력 상태
- "혼자 먼저 입력하기" 버튼
- "배우자 초대 다시 보내기" 버튼

상태:

- 배우자 참여 전
- 배우자 참여 후 한 명만 입력
- 둘 다 입력 중
- 둘 다 완료

#### 화면: 개인 정보 입력

목적:
각자의 기본 정보를 입력한다.

입력:

- 이름 또는 닉네임
- 휴대폰 인증 여부
- 직장 지역
- 소득 구간
- 자산 구간
- 공개 범위

주의:

- 정확한 소득과 자산 금액은 받지 않는다.
- 상대에게 공개할 범위를 사용자가 선택할 수 있어야 한다.
- 공개 범위의 기본값은 보수적으로 정한다: 확정 필요

#### 화면: 커플 공통 정보 입력

목적:
시나리오 계산과 정책 매칭에 필요한 커플 공통 정보를 입력한다.

입력:

- 결혼 예정일
- 예식 지역
- 거주 희망 지역
- 주거 형태
- 예산 총액
- 보유 현금 구간 또는 금액 방식: 확정 필요
- 가족 지원금 여부
- 대출 고려 여부
- 자녀 계획
- 선호 예식 스타일
- 입주 예정 시점

주의:

- 대출 가능 여부를 판단하지 않는다.
- 자녀 계획은 민감할 수 있으므로 선택 안 함을 허용한다.

#### 화면: 온보딩 확인 화면

목적:
사용자가 입력한 내용을 제출 전에 확인한다.

표시 요소:

- 개인 입력 요약
- 커플 공통 입력 요약
- 배우자 입력 완료 여부
- 수정 버튼
- 시나리오 만들기 버튼

완료 조건:

- 필수 입력값이 채워져 있어야 한다.
- 배우자 입력이 필요한 항목은 상태를 명확히 보여준다.

#### 화면: 시나리오 생성 화면

목적:
온보딩 값을 바탕으로 신혼 비용 시나리오를 만든다.

입력 또는 조정:

- 예식 비용
- 주거 초기 비용
- 월 부담
- 혼수
- 가전
- 가구
- 허니문
- 기타 비용

표시 요소:

- 자동 입력된 값과 직접 수정 가능한 값 구분
- sample 값 표시
- 저장 버튼
- 결과 보기 버튼

#### 화면: 시나리오 결과 화면

목적:
커플이 총액, 월 부담, 부족 금액, 위험 신호를 함께 확인한다.

표시 요소:

- 예상 총액
- 항목별 비용 카드
- 월 부담 카드
- 부족 금액
- 위험 신호
- 다음 행동 제안
- 정책 매칭 보기 버튼
- 파트너 상품 비교 보기 버튼

주의 문구:

- "이 결과는 입력값 기준의 예상 계산이에요."
- "대출 가능 여부나 정책 선정 결과를 뜻하지 않아요."

### 5.2 분기와 예외

#### 배우자가 아직 참여하지 않음

- 본인은 개인 입력과 일부 공통 정보를 먼저 저장할 수 있다.
- 배우자 입력이 필요한 항목은 "배우자 참여 후 확인 가능"으로 표시한다.
- 공동 승인, 상담 신청은 막는다.

#### 배우자가 참여했지만 온보딩을 완료하지 않음

- 누가 어느 단계까지 입력했는지 표시한다.
- 상대에게 알림 보내기 버튼 제공
- 한 사람의 입력만으로 가능한 임시 시나리오는 "임시"로 표시한다.

#### 새로고침 또는 앱 종료 후 복귀

- 마지막 저장된 단계로 복구한다.
- 저장되지 않은 입력은 복구할 수 없음을 안내한다.

#### 필수 입력 누락

- 필드별 오류 메시지를 표시한다.
- 화면 상단에 첫 오류로 이동하는 안내를 둔다.

#### 민감 정보 공개 범위 충돌

- 상대에게 보이지 않는 값은 결과 화면에서도 구간 또는 비공개로 표시한다.
- 계산에 사용된 경우 "비공개 값이 계산에 반영됨" 정도로만 표시한다.

#### 시나리오 계산 실패

- 입력값 오류면 수정 안내
- 서버 오류면 다시 시도
- 계산 규칙 버전 오류면 운영자 확인 필요 상태 표시

## 6. 정책 매칭 결과 확인

### 6.1 기본 흐름

#### 화면: 정책 매칭 시작 화면

목적:
사용자가 정책 매칭에 필요한 정보와 주의사항을 확인한다.

표시 요소:

- 정책 매칭 설명
- 필요한 입력값 목록
- 결과 상태 안내
- "최종 선정 결과가 아니에요" 안내
- 시작 버튼

#### 화면: 추가 정보 입력 화면

목적:
온보딩에서 부족한 정보를 추가로 받는다.

입력:

- 거주 예정 지역
- 혼인 상태 또는 예정 상태
- 자녀 계획 여부: 선택 안 함 허용
- 소득 구간
- 자산 구간
- 기타 정책별 필요 정보

주의:

- 정책별 필요한 정보만 요청한다.
- 불필요한 개인정보를 받지 않는다.

#### 화면: 정책 결과 목록

목적:
커플에게 맞을 수 있는 정책을 상태별로 보여준다.

표시 요소:

- 정책명
- 결과 상태
- 결과 이유
- 출처
- 기준일
- 검증일
- 필요한 추가 정보
- 필요 서류
- 상세 보기 버튼

결과 상태:

- likely_eligible: 가능성이 있어 보임
- maybe_eligible: 조건 확인이 더 필요함
- not_eligible: 현재 입력 기준으로 어려워 보임
- need_more_info: 정보가 더 필요함
- expired: 기간이 지남
- unknown: 판단할 수 없음

#### 화면: 정책 상세

목적:
정책별 조건, 사유, 필요 서류, 다음 행동을 보여준다.

표시 요소:

- 정책 요약
- 대상 조건
- 입력값 기준 결과
- 판단 사유
- 부족한 정보
- 필요 서류
- 출처 URL
- 기준일과 검증일
- 할 일로 추가 버튼

주의 문구:

- "최종 선정은 기관 심사 결과에 따라 달라질 수 있어요."
- "정책 기준은 바뀔 수 있어요. 기준일과 출처를 확인해 주세요."

### 6.2 분기와 예외

#### 필요한 정보가 부족함

- 결과 상태를 need_more_info로 표시한다.
- 어떤 정보가 필요한지 목록으로 보여준다.
- 추가 입력 화면으로 이동하는 버튼을 제공한다.

#### 정책 출처가 없거나 검증일이 오래됨

- unknown 또는 검증 필요 상태로 표시한다: 상태명 확정 필요
- 사용자에게 확정적인 안내를 하지 않는다.
- 운영자 검증 대상에 포함한다.

#### 정책이 만료됨

- expired로 표시한다.
- 기본 추천 목록에서는 낮은 우선순위로 둔다.
- 만료된 정책을 숨길지 표시할지는 확정 필요

#### 배우자 입력이 필요한데 배우자가 미참여

- 배우자 초대 또는 입력 요청 안내를 보여준다.
- 가능한 임시 결과는 임시 배지로 표시한다.

#### 정책 결과를 할 일로 추가

- 필요 서류와 마감일이 있으면 Task 생성 대상으로 넘긴다.
- 사용자가 정책 결과에서 문서·할 일 만들기를 실행하면 Task와 Document가 생성된다.
- 마감일이 있으면 인앱 Notification이 저장된다.

## 7. 파트너 상품 비교 → 비교방 → 둘 다 승인 → 상담 신청

### 7.1 기본 흐름

#### 화면: 파트너 상품 목록

목적:
커플이 지역, 예산, 카테고리 기준으로 상품을 찾는다.

표시 요소:

- 카테고리 필터
- 지역 필터
- 예산 필터
- 상품 카드
- 가격 검증 배지
- 유효기간
- 예상 총액

주의:

- "최저가" 표현은 운영 기준 확정 전까지 사용하지 않는다.
- 유효기간이 지난 가격은 기본 노출하지 않는다.

#### 화면: 상품 상세

목적:
상품 가격과 포함 항목을 자세히 확인한다.

표시 요소:

- 파트너 이름
- 상품명
- 기본 가격
- 예상 총액
- 포함 항목
- 사실상 필수 옵션
- 선택 옵션
- 추가 비용 가능성
- 검증일
- 유효기간
- 비교방에 담기 버튼

#### 화면: 비교방 생성 또는 선택

목적:
사용자가 상품을 비교할 공간을 만든다.

표시 요소:

- 새 비교방 만들기
- 기존 비교방 선택
- 비교방 이름
- 현재 담긴 상품 수

제약:

- 한 비교방에는 2개에서 4개 상품을 비교한다.
- 상품 1개만 있어도 draft 상태로 저장할 수 있는지는 확정 필요

#### 화면: 비교방

목적:
두 사람이 상품을 나란히 보고 의견을 남기고 승인한다.

표시 요소:

- 2개에서 4개 비교 카드
- 각 상품의 예상 총액
- 포함 항목
- 필수 옵션
- 선택 옵션
- 검증일과 유효기간
- 댓글
- 각자 승인/보류/반려 버튼
- 배우자 결정 상태
- 결정 로그

상태:

- draft
- shared
- waiting_partner
- both_approved
- rejected
- archived

#### 화면: 공동 승인 완료

목적:
둘 다 승인된 상태를 확인하고 상담 신청으로 이동한다.

표시 요소:

- 승인한 사람
- 승인 시각
- 승인한 상품
- 상담 신청 버튼
- "상담 신청 전 개인정보 제공 동의가 필요해요" 안내

#### 화면: 상담 신청

목적:
승인된 상품에 대해 파트너 상담을 신청한다.

입력:

- 상담 희망일
- 연락 방식
- 연락처: 확정 필요
- 문의 내용
- 개인정보 제공 동의

표시 요소:

- 전송될 정보 요약
- 파트너에게 제공되는 개인정보 범위
- 동의 체크박스
- 신청 버튼

#### 화면: 상담 신청 확인

목적:
리드 전송 전 사용자가 마지막으로 확인한다.

표시 요소:

- 신청 상품
- 파트너
- 상담 희망일
- 연락 방식
- 제공 정보
- 뒤로가기 버튼
- 최종 신청 버튼

완료 후:

- LeadRequest 생성
- 상태는 submitted
- 완료 화면으로 이동

#### 화면: 상담 신청 완료

목적:
사용자에게 접수 상태와 다음 단계를 안내한다.

표시 요소:

- 신청 완료 메시지
- 리드 상태
- 예상 응답 안내: 운영 기준 확정 필요
- 신청 내역 보기 버튼

### 7.2 분기와 예외

#### 비교방에 상품이 1개뿐임

- 비교를 위해 상품을 더 담으라고 안내한다.
- 상담 신청은 막는다.

#### 비교방에 상품이 4개를 초과함

- 더 추가할 수 없다고 안내한다.
- 기존 상품 제거 후 추가하도록 한다.

#### 배우자가 아직 참여하지 않음

- 비교방 저장은 가능하게 할 수 있다: 확정 필요
- 공동 승인과 상담 신청은 막는다.
- 배우자 초대 안내를 보여준다.

#### 한 명만 승인함

- 상태는 waiting_partner로 표시한다.
- 상대에게 승인 요청 알림을 보낼 수 있다.
- 상담 신청 버튼은 비활성화한다.

#### 한 명이 보류함

- 상태는 waiting_partner 또는 hold 포함 상태로 표시한다: 확정 필요
- 상담 신청은 막는다.
- 댓글로 보류 이유를 남기도록 유도한다.

#### 한 명이 반려함

- 비교방 상태는 rejected로 바뀐다.
- 상담 신청은 막는다.
- 다시 검토할 수 있는 reopen 정책은 확정 필요

#### 가격 유효기간이 상담 신청 전에 만료됨

- 상담 신청 전 확인 화면에서 만료 안내를 보여준다.
- 신청을 막을지, 운영자 확인 요청으로 보낼지는 확정 필요

#### 개인정보 제공 동의를 하지 않음

- 상담 신청을 막는다.
- 어떤 정보가 왜 필요한지 짧게 안내한다.

#### 리드 생성 실패

- 입력 오류면 필드별 안내
- 권한 오류면 커플 멤버 여부 확인 안내
- 서버 오류면 다시 시도
- 중복 신청이면 기존 신청 내역으로 이동

## 8. 홈 화면 와이어프레임

### 화면: 홈

목적:
커플의 현재 진행 상태와 다음 행동을 보여준다.

표시 영역:

- 커플 이름
- 배우자 참여 상태
- 온보딩 진행률
- 최근 시나리오
- 정책 매칭 요약
- 비교방 요약
- 상담 신청 상태
- 다음 할 일

주요 CTA:

- 배우자 초대하기
- 온보딩 이어하기
- 시나리오 보기
- 정책 확인하기
- 상품 비교하기
- 상담 신청 내역 보기

빈 상태:

- 커플이 없으면 커플 생성 안내
- 배우자가 없으면 초대 안내
- 시나리오가 없으면 시나리오 만들기 안내
- 비교방이 없으면 상품 비교 시작 안내

## 9. 관리자와 파트너 기본 흐름

### 운영자 흐름

1. 운영자 로그인
2. 대시보드 확인
3. 정책 프로그램 등록 또는 수정
4. 정책 룰 버전 등록
5. 파트너 등록
6. 상품과 가격 버전 등록
7. 가격 검증 상태 변경
8. 리드 목록 확인
9. 리드 상태 변경
10. 주요 변경 로그 확인

주의:

- 운영자 권한 없는 사용자는 접근할 수 없다.
- 가격과 정책 변경은 audit log가 필요하다.
- 정책과 가격은 출처, 기준일, 검증일을 가져야 한다.

### 파트너 흐름

1. 파트너 사용자 로그인
2. 본인 업체 리드 목록 확인
3. 리드 상세 확인
4. 상태 변경
5. 상담 결과 입력

주의:

- 파트너는 본인 업체의 리드만 볼 수 있다.
- 개인정보는 필요한 범위로 마스킹한다.
- 파트너 셀프 가입은 MVP 제외다.

## 10. 알림과 상태 복구

### 알림이 필요한 순간

- 배우자 초대 발송
- 배우자 초대 수락
- 배우자 온보딩 미완료
- 시나리오 생성 완료
- 비교방 공유
- 한 명이 승인, 보류, 반려
- 둘 다 승인
- 상담 신청 완료
- 리드 상태 변경
- 할 일 마감일 도래

### 상태 복구 원칙

- 온보딩은 단계별 저장을 기본으로 한다.
- 시나리오는 계산 버전과 함께 저장한다.
- 비교방 결정은 DecisionLog로 남긴다.
- 상담 신청은 중복 신청을 막아야 한다.
- 분석 이벤트 실패가 사용자 기능을 막으면 안 된다.

## 11. 확정 필요 사항

- 가입 식별자를 이메일로 할지 휴대폰으로 할지
- CoupleMember 역할명과 권한 범위
- 배우자 거절 상태를 저장할지 여부
- 커플 이동 또는 탈퇴 정책
- 개인 민감 정보 공개 범위 기본값
- 보유 현금을 구간으로 받을지 금액으로 받을지
- 상품 1개 비교방 저장 허용 여부
- 보류 상태의 비교방 상태값
- 반려된 비교방의 재검토 정책
- 가격 만료 시 상담 신청 차단 여부
- 파트너에게 제공할 최소 개인정보 범위
- 리드 응답 예상 시간 안내 기준
