# 신혼생활 UX 품질 리뷰

작성일: 2026-06-05

범위: `apps/web` 사용자 앱의 현재 MVP 화면과 핵심 흐름.

## 요약

현재 앱은 기능별 진입점, 카드 기반 정보 구조, 로딩/빈/에러 상태의 기본 골격을 갖췄다. 다만 실제 사용자 출시 전에는 모바일에서 긴 폼을 완주하게 돕는 단계 안내, 승인/상담 신청의 다음 행동 명확성, 정책 결과 오해 방지, 접근성 라벨과 키보드 이동 품질을 더 다듬어야 한다.

## 문제 목록과 개선 제안

| 우선순위 | 영역        | 문제                                                                                                         | 개선 제안                                                                                              |
| -------- | ----------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| P1       | 모바일 폼   | 온보딩과 시나리오 입력은 모바일에서 한 화면에 많은 필드가 이어진다. 완료까지의 남은 양이 즉시 보이지 않는다. | 섹션별 저장 상태, 필수 항목 잔여 개수, 하단 고정 저장 버튼을 추가한다.                                 |
| P1       | 공동 승인   | 비교방에서 왜 카드 2개와 배우자 참여가 필요한지 사용자가 실패 후에야 알 수 있다.                             | 비교방 상단에 `승인 가능 조건` 상태판을 항상 노출하고 부족 조건을 바로가기와 함께 표시한다.            |
| P1       | 정책 결과   | `likely_eligible`, `maybe_eligible` 문구가 사용자에게 실제 선정 가능성처럼 읽힐 수 있다.                     | 결과 배지를 `준비 가능성`, `추가 확인 필요`처럼 낮은 확정성 문구로 바꾸고 공식 공고 확인 CTA를 붙인다. |
| P1       | 상담 신청   | 상담 신청 시 어떤 비교 카드가 파트너에게 전달되는지 더 명확히 보여야 한다.                                   | 선택된 카드의 상품명, 가격 버전, 유효기간, 둘의 승인 상태를 제출 버튼 바로 위에 요약한다.              |
| P2       | 로딩 상태   | 일부 클라이언트 화면은 데이터 로딩 중 기본 로딩 상태만 보이고, 지연이 길 때 사용자가 할 수 있는 행동이 없다. | 8초 이상 지연 시 재시도 버튼과 토큰 확인 안내를 노출한다.                                              |
| P2       | 빈 상태     | 상품, 정책, 콘텐츠가 없을 때 다음 행동이 화면마다 조금씩 다르다.                                             | 빈 상태 컴포넌트의 CTA 패턴을 통일하고 `가입`, `온보딩`, `관리자 입력` 중 필요한 다음 단계만 보여준다. |
| P2       | 한국어 문구 | 관리자와 사용자 앱 모두 일부 상태값이 `draft`, `verified`, `both_approved`처럼 원문으로 노출된다.            | 사용자 화면은 한국어 상태 라벨로 변환하고, 관리자 화면은 원문+한국어를 병기한다.                       |
| P2       | 접근성      | 카드형 링크와 버튼이 섞여 있어 키보드 사용자에게 동작 차이가 덜 명확할 수 있다.                              | 링크는 목적지 이동, 버튼은 상태 변경으로 역할을 엄격히 구분하고 aria-label을 보강한다.                 |
| P2       | 색상 대비   | 연한 배경의 작은 회색 보조 문구는 일부 모바일 화면에서 대비가 낮을 수 있다.                                  | 보조 텍스트 색상을 한 단계 진하게 조정하고 13px 이하 텍스트 사용을 줄인다.                             |
| P3       | 콘텐츠 상세 | FAQ와 CTA가 붙었지만 글의 길이가 길어질 때 목차나 요약 앵커가 없다.                                          | 긴 글에는 상단 요약, 관련 계산기 CTA, FAQ 앵커를 제공한다.                                             |
| P3       | 관리자 CRM  | 운영 탭이 늘어나면서 한 화면에서 탭 개수가 많아졌다.                                                         | 탭을 `파트너 운영`, `콘텐츠`, `분석` 그룹으로 나누거나 좌측 내비게이션으로 전환한다.                   |

## 긍정적인 부분

- 첫 화면에서 가입, 초대, 온보딩, 시나리오, 정책, 상품, 비교방, 문서함, 할 일, 콘텐츠, 계산기로 이어지는 IA가 명확하다.
- 가격 카드는 포함 항목, 필수 옵션, 유효기간, 검증 상태를 함께 보여 가격 오해를 줄이는 방향이다.
- 리드와 파트너 화면은 직접 개인정보를 기본 마스킹해 노출 부담을 줄인다.
- Playwright 모바일 viewport 테스트가 추가되어 핵심 흐름의 회귀를 잡을 수 있다.

## 출시 전 UX 체크

- 모바일 390px, 430px, 768px에서 모든 주요 폼의 버튼과 텍스트 겹침 확인.
- 키보드만으로 가입, 온보딩 저장, 시나리오 생성, 비교방 승인, 상담 신청 완료 확인.
- 스크린리더에서 주요 입력의 label, 에러 메시지, 상태 배지가 읽히는지 확인.
- 정책 결과와 가격 카드 문구를 법무/운영 검토 후 확정.
- 사용자 테스트 3명 이상으로 초대, 공동 승인, 상담 신청 흐름의 막힘 지점 기록.
