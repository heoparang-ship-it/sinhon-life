# 신혼OS PRD

## 1. 서비스 정의

신혼OS는 예비 신혼부부와 혼인 초기 부부가 예산, 주거, 정책 혜택, 파트너 상품 비교, 공동 승인, 상담 신청을 함께 진행하는 커플 중심 실행 서비스다.

## 2. 핵심 사용자

### 예비 신혼부부

결혼 준비를 시작했거나 진행 중인 커플이다. 예식, 주거, 혼수, 가전, 가구, 허니문, 가족 지원금, 대출 고려 여부 등 여러 결정을 동시에 해야 한다.

### 혼인 5년 이내 부부

결혼 이후에도 주거, 정책 혜택, 생활 비용, 자녀 계획, 이사, 가전 교체 등 공동 결정을 이어가는 커플이다.

### 파트너 업체

웨딩, 주거, 가전, 가구, 상담 등 신혼 준비와 생활에 필요한 상품 또는 서비스를 제공하는 업체다. 가격, 포함 항목, 필수 옵션, 유효기간이 검증된 정보를 제공해야 한다.

### 운영자

정책 데이터, 파트너 데이터, 가격 검증, 리드 상태, 콘텐츠 품질, 사용자 문의를 관리하는 내부 사용자다.

## 3. 사용자별 문제

### 예비 신혼부부의 문제

- 결혼 준비 비용이 항목별로 흩어져 있어 총액을 파악하기 어렵다.
- 한 사람이 알아본 내용을 다른 사람이 같은 수준으로 이해하기 어렵다.
- 예식, 주거, 혼수, 허니문 비용이 동시에 발생해 우선순위를 정하기 어렵다.
- 정책 혜택을 찾기 어렵고, 우리 커플에게 맞는지 판단하기 어렵다.
- 업체 가격이 실제 총액인지, 어떤 옵션이 포함되는지 알기 어렵다.
- 둘 중 한 명만 결정한 상태로 상담이나 계약이 진행될 수 있다.

### 혼인 5년 이내 부부의 문제

- 결혼 이후 주거, 이사, 자녀 계획, 정책 혜택 등 새 결정이 계속 생긴다.
- 결혼 전 예산과 실제 생활 비용의 차이를 함께 점검하기 어렵다.
- 정책이나 혜택이 바뀌어도 기준일과 출처를 확인하기 어렵다.
- 필요한 서류와 할 일을 놓치기 쉽다.

### 파트너 업체의 문제

- 단순 문의가 많고, 실제 상담 의사가 있는 커플을 구분하기 어렵다.
- 가격을 낮게 보이게만 전달하면 이후 신뢰 문제가 생길 수 있다.
- 상담 전에 커플이 어떤 조건과 예산을 원하는지 알기 어렵다.
- 리드 상태와 상담 결과를 체계적으로 관리하기 어렵다.

### 운영자의 문제

- 정책 정보와 가격 정보는 자주 바뀌며, 출처와 기준일 관리가 필요하다.
- 파트너 가격 검증과 만료 처리를 수동으로 놓치기 쉽다.
- 사용자에게 금융성 오해를 주지 않도록 문구와 결과 상태를 관리해야 한다.
- 개인정보와 리드 정보를 안전하게 다뤄야 한다.

## 4. MVP에 반드시 들어갈 기능

### 커플 계정과 초대

- 가입 또는 로그인
- 커플 생성
- 배우자 초대 링크 생성
- 초대 수락
- 커플 멤버 역할 관리
- 초대 만료와 이미 다른 커플 소속인 사용자 예외 처리

### 공동 온보딩

- 개인별 기본 정보 입력
- 커플 공통 정보 입력
- 결혼 예정일, 예식 지역, 거주 희망 지역, 주거 형태, 예산 총액 입력
- 소득, 자산 등 민감 정보는 구간으로 입력
- 단계별 저장, 뒤로가기, 새로고침 복구
- 배우자 미참여 상태 안내

### 시나리오 생성과 결과 확인

- 예식 비용, 주거 초기 비용, 월 부담, 혼수, 가전, 가구, 허니문 등 주요 항목 입력
- 총액과 월 부담 계산
- 부족 금액과 위험 신호 표시
- 계산 버전 저장
- 출처 없는 수치는 sample로 구분

### 정책 매칭

- 샘플 정책 데이터 등록
- 정책별 출처, 기준일, 검증일, 룰 버전 표시
- 커플 입력값 기준의 자격 가능성 결과 표시
- 결과 상태값 표시: likely_eligible, maybe_eligible, not_eligible, need_more_info, expired, unknown
- 필요한 추가 정보와 필요 서류 표시
- 최종 선정이나 승인으로 오해되지 않는 안내 문구

### 파트너 상품 비교

- 파트너 업체와 상품 목록
- 상품 상세
- 가격 버전 표시
- 기본 가격, 예상 총액, 포함 항목, 사실상 필수 옵션, 선택 옵션 표시
- 검증일, 유효기간, 만료 상태 표시
- 지역, 예산, 카테고리 필터

### 비교방과 공동 승인

- 상품을 비교방에 추가
- 2개에서 4개 카드 비교
- 각자 승인, 보류, 반려
- 댓글
- 둘 다 승인한 경우에만 상담 신청 단계로 이동
- 모든 결정은 누가 언제 무엇을 했는지 기록

### 상담 신청과 리드 생성

- 둘 다 승인된 비교방에서만 상담 신청 가능
- 상담 희망일과 연락 방식 선택
- 개인정보 제공 동의
- 전송 전 확인 화면
- 리드 상태 관리
- 운영자와 파트너의 기본 조회 화면

### 문서함, 할 일, 알림 기본 구조

- 필요 서류 체크리스트
- 할 일 생성
- 담당자 지정
- 마감일
- 완료 처리
- 정책 결과의 필요 서류를 할 일로 추가
- 알림 저장 구조

### 관리자 기본 기능

- 운영자 권한
- 파트너, 상품, 가격 버전 관리
- 정책 프로그램 관리
- 리드 목록과 상태 변경
- 주요 변경 기록 저장

### 분석 이벤트

- 주요 퍼널 이벤트 수집
- 계정 생성, 커플 생성, 초대, 온보딩 완료, 시나리오 생성, 정책 확인, 상품 비교, 공동 승인, 리드 신청 이벤트
- 이벤트 payload에는 개인정보를 저장하지 않음

## 5. MVP에서 제외할 기능

- 실결제
- 예약금 결제
- 자동 정산
- 파트너 셀프 가입
- 파트너 대량 엑셀 업로드
- 실제 금융 심사 또는 대출 한도 산정
- 외부 금융 API 연동
- 외부 정책 API 자동 연동
- 주민등록번호 입력
- 민감 서류 원본 업로드 강제
- 복잡한 CMS 에디터
- 사용자 댓글형 커뮤니티
- 자동 계약 확정
- 최저가 보장 기능
- AI가 정책 자격이나 금융 가능성을 확정하는 기능

## 6. 단계별 범위

### 6주 MVT

목표는 사용자가 "커플 기준으로 총액과 선택지를 같이 볼 가치가 있는지"를 검증하는 것이다.

- AGENTS.md와 핵심 문서 작성
- 모노레포와 기본 개발 환경 구성
- 커플 생성과 배우자 초대
- 공동 온보딩 기본 플로우
- 샘플 입력 기반 시나리오 계산
- 샘플 정책 5개 매칭
- 샘플 파트너 상품과 가격 카드
- 비교방과 둘 다 승인 흐름
- 상담 신청 전 단계까지의 검증
- 모바일 기준 핵심 화면
- 주요 이벤트 로깅 기본 구조

### 12주 MVP

목표는 실제 운영자가 관리하는 데이터와 리드 흐름을 붙여 제한된 사용자에게 운영 가능한 수준을 만드는 것이다.

- 리드 생성과 상태 관리
- 운영자 관리자 화면
- 파트너 상품, 가격 버전, 검증일, 유효기간 관리
- 정책 프로그램과 룰 버전 관리
- 문서함, 할 일, 알림 기본 기능
- 상담 신청 전 개인정보 제공 동의
- 파트너용 리드 상세 기본 화면
- 핵심 E2E 테스트
- 보안 리뷰와 UX 리뷰
- 출시 체크리스트

### 24주 Beta

목표는 제한된 파트너와 실제 사용자를 대상으로 운영 품질을 높이는 것이다.

- 파트너 CRM 개선
- 가격 데이터 만료와 재검증 운영 흐름
- 정책 데이터 업데이트 운영 흐름
- 콘텐츠와 SEO 랜딩
- 퍼널 대시보드
- 고객지원 운영 도구
- 장애 대응과 롤백 체계
- 제한된 결제 샌드박스 검토
- 개인정보 처리와 법무 검토 반영
- 파트너 리드 품질 측정

## 7. 성공 지표

- 가입한 사용자 중 커플 생성 완료율
- 초대 링크 발송 후 배우자 참여율
- 공동 온보딩 완료율
- 시나리오 생성 완료율
- 정책 매칭 결과 확인율
- 파트너 상품 상세 조회율
- 비교방 생성율
- 비교방에서 둘 다 승인까지 도달한 비율
- 상담 신청 전 확인 화면 도달율
- 개인정보 제공 동의 후 리드 제출율
- 리드 제출 후 파트너가 확인한 비율
- 가격 카드에서 검증일과 유효기간을 확인한 비율
- 사용자가 정책 결과에서 필요 서류 또는 다음 할 일을 추가한 비율
- 모바일 핵심 흐름 완료율

## 8. 실패 지표

- 가입 후 커플 생성 전 이탈률이 높음
- 초대 링크를 보냈지만 배우자 참여율이 낮음
- 온보딩 중 민감 정보 입력 단계에서 이탈률이 높음
- 시나리오 결과를 본 뒤 다음 행동으로 이어지지 않음
- 정책 결과를 승인 또는 선정으로 오해하는 문의가 많음
- 가격 카드의 예상 총액과 실제 상담 가격 차이에 대한 불만이 많음
- 둘 다 승인하지 않은 상태에서 상담 신청을 시도하는 사용자가 많음
- 리드 제출 후 파트너 응답률이 낮음
- 운영자가 가격 검증일과 유효기간을 제때 관리하지 못함
- 개인정보 관련 문의 또는 삭제 요청 처리에 시간이 오래 걸림
- 모바일에서 주요 버튼이나 입력 UI 사용 불편이 반복 보고됨

## 9. 개인정보·금융 관련 주의사항

- 소득, 자산, 보유 현금, 대출 고려 여부 등은 민감한 정보로 본다.
- MVP에서는 정확한 금액보다 구간 입력을 우선한다.
- 주민등록번호는 입력받지 않는다.
- 전화번호 등 직접 식별 정보는 리드 생성에 꼭 필요한 경우에만 수집한다.
- 개인정보 제공 동의 없이 파트너에게 리드를 전송하지 않는다.
- 파트너와 운영자 화면에서는 개인정보를 기본 마스킹한다.
- 분석 이벤트에는 이름, 전화번호, 계좌, 파일명, 상세 소득, 상세 자산을 저장하지 않는다.
- 정책 결과는 가능성 안내이며 최종 선정 결과가 아니다.
- 대출 가능, 금리 확정, 한도 확정, 승인 보장처럼 보이는 표현을 쓰지 않는다.
- 금융 상품 추천이나 심사처럼 보이는 기능은 MVP 범위에서 제외한다.
- 결제 기능은 별도 설계 문서, 법무 검토, 보안 검토 이후에만 다룬다.

## 10. 파트너 가격 데이터 운영 원칙

- 파트너 가격은 기본 가격과 예상 총액을 분리해서 관리한다.
- 포함 항목, 사실상 필수 옵션, 선택 옵션을 분리해서 표시한다.
- 가격마다 검증일과 유효기간을 가진다.
- 유효기간이 지난 가격은 기본 노출하지 않는다.
- 미검증 가격은 검증된 가격과 다른 배지로 표시한다.
- "최저가" 표현은 운영 기준이 확정되기 전까지 사용하지 않는다.
- 가격 변경은 새 버전으로 남긴다.
- 가격을 변경한 운영자, 변경 시각, 변경 이유를 기록한다.
- 상담 신청 전에 사용자가 가격 유효기간과 추가 비용 가능성을 볼 수 있어야 한다.
- 실제 계약, 환불, 위약금, 예약금 정책은 파트너 계약 기준 확정 필요로 남긴다.

## 11. 확정 필요 사항

- 혼인 5년 이내 부부의 정확한 서비스 범위
- MVP에서 다룰 파트너 카테고리 우선순위
- 샘플 정책 5개의 선정 기준
- 예산 구간, 소득 구간, 자산 구간의 구체 범위
- 리드 전달 시 파트너에게 제공할 최소 개인정보 범위
- 가격 검증 주기
- 정책 데이터 검증 주기
- 고객지원 운영 시간과 응답 기준
